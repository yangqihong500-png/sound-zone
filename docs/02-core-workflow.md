# 02 · 核心工作逻辑

## 域的生命周期（五步闭环）

```
1. 创建域
   上传 ≥3 首歌 + 场景命名（如「日本 solo trip」）
        │
        ▼
2. 场景分发
   把域推给「正在做同件事」的用户（首页只推此刻活跃的域）
        │
        ▼
3. 同频收听 + 点歌
   实时队列 · 点赞加权 · 轮转公平 · AI DJ 兜底
        │
        ▼
4. 碎片发布
   照片/文案自动绑定当下配乐 → 结构化三元组数据
        │
        ▼
5. 沉淀与反哺
   域歌单每日自动生成（异步资产）· 三元组数据进配乐模型
```

### 第 1 步：创建域
- 门槛极低：≥3 首歌 + 一个场景名即可开域
- 场景名自由文本 + 系统归一化为场景标签（如"考研自习""自习室""图书馆刷题"归为同一类），避免流量过度分散

### 第 2 步：场景分发
- 首页信息流 = "此刻活跃的同频域"，按 用户画像 × 场景标签 匹配排序
- **只推活跃域**（有播放流、近 N 分钟有点歌/碎片行为），规避空房间的第一道闸门
- 分发话术示例："372 个正在夜跑的人在这个域里"

### 第 3 步：同频收听与点歌队列

**队列排序公式**（核心机制）：

```
队列得分 = 点赞数 × 2 + 域主加成 × 3 − 该用户近 1 小时已播点歌数 × 1.5
```

- 点赞权重最高 → 好歌品实时浮现
- 轮转惩罚 → 防止单人刷屏，保证公平
- 域主加成 → 域主保留控场权，对域的氛围负责

**AI DJ 兜底**（解决空房间问题）：
- 当队列将空且无人点歌时，AI DJ 根据该域历史碎片的配乐偏好 + 场景标签自动补歌
- 长尾域没人同时在线时，域仍可异步运转：点歌排队、碎片持续累积、来访者可"回放"近期的域电台流

### 第 4 步：碎片发布
- 用户发照片/文案时，系统自动带上"此刻在听"的音乐水印（可关闭）
- 每条碎片 = (场景标签, 图片/文案, 配乐, 时间戳) 结构化数据 —— 数据飞轮的源头（见 03 文档）

### 第 5 步：沉淀与反哺
- **域歌单沉淀**：每日 24:00 自动将当日域内播放+高赞点歌生成静态歌单，可订阅、可分享到站外 —— 域的异步资产，也是拉新入口
- **数据反哺**：三元组数据进入配乐推荐模型，模型能力回流提升域内体验（AI DJ、发碎片时的智能配乐推荐）

## 成长体系：歌品值

**歌品值 = 你的点歌被点赞率**（辅以域主等级、碎片获赞数）

- 把"审美"量化成可展示的资产，直接回应"想 show 歌品但没流量"的痛点
- 歌品值高的用户获得：点歌队列初始权重加成、域主页展示位、官方域客座域主资格
- 个人主页 = "审美身份证"：擅长场景、代表点歌、歌品值曲线

## 两个关键风险的预案

| 风险 | 预案 |
|------|------|
| 空房间（长尾域死寂） | AI DJ 兜底、异步点歌排队、首页只推活跃域、场景标签归一化聚流 |
| 点歌冲突 | 队列得分公式 + 域主管理权（置顶/移除/锁队列） |

另需平台侧配套：UGC 图片/文案内容审核；实时共听的版权需在 TME 曲库授权框架内（QQ音乐"一起听"已验证该模式可行）。
