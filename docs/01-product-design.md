# 01 · 产品设计

> **版本说明**：v2（2026-09-24）—— 按第二次会议决议修订。与 v1 冲突处以本文为准（播放 FIFO、取消歌品值、公开/私密域、图片绑定逻辑、视觉规范定稿等，详见会议记录 2026-09-24）。

## 产品定位

**同频 SoundZone**：独立运行的 App / H5 音乐产品 Demo，基于场景命名的实时共听社区。uni-app 同时保留小程序构建能力；2026-09-25 的独立产品决策覆盖此前“必须运行在音乐 App 内部”的假设。

- 不是歌单工具，而是**场景电台**——歌单是"结果"，域是"过程"
- 曲库通过可替换 Provider 接入；Demo 使用 Audius 官方开放曲库和已获在线播放许可的小曲库，**不提供用户音频上传**
- 2026-09-27 增加关注关系内的一对一文字私信；Following 列表和已关注用户主页提供入口

## 痛点分析

### 痛点 1：普通人的审美表达没有流量
用户想 show 自己的歌品和审美，但在现有音乐平台分享歌单，除非是大 V，否则几乎无人看到。审美表达欲被压抑。

### 痛点 2：同审美、同爱好的社交缺位
现有音乐社交（评论区的、一起听）要么太泛（歌曲评论区人群混杂），要么太重（一起听需要先有好友关系）。"正在做同件事的人"这个最自然的连接维度没有被产品化。

## 核心洞察

**「域名 = 正在做的事」是整个产品最值钱的设计。**

传统歌单按"曲风/情绪"分类，要求用户先懂音乐、会描述心情；而「考研自习」「日本 solo trip」「拼豆」「夜跑」这种场景命名：

- 用户不需要任何音乐知识就能找到归属，分发门槛降为零
- 场景天然带时间和状态语义（深夜、通勤、专注），比"伤感""治愈"更精准
- 场景无限细分，任何正在做的事都可以成为一个域，长尾供给充足

## 核心概念：域（Zone）

一个域由三部分组成：

```
┌─────────────────────────────────────┐
│  域 · 考研自习室（场景容器）          │
│  ┌─────────────────────────────────┐│
│  │ 同频电台 · 实时播放流            ││
│  │ 所有人同步听同一首歌             ││
│  └─────────────────────────────────┘│
│  ┌──────────────┐ ┌────────────────┐│
│  │ 点歌台        │ │ 碎片墙          ││
│  │ 曲库点歌      │ │ 照片/文案       ││
│  │ 上传顺序 FIFO │ │ 绑定上传的歌曲  ││
│  └──────────────┘ └────────────────┘│
└─────────────────────────────────────┘
   域主：建域 + 初始歌单 + 管理
   同频者：收听 + 点歌 + 发碎片
```

- **同频电台**：实时播放流，所有在域成员同步收听；不可暂停/切歌，按上传顺序（FIFO）播放（2026-09-24 决议 D3）
- **上传队列**：成员从已接入曲库选择歌曲，按上传顺序等待播放；单用户单域 5 分钟限传 1 首，当前曲与待播队列均为空时立即解除冷却以便补歌
- **动态区**：成员上传歌曲时可选附一张照片分享当下，图片保留具体队列条目归属；域内预览按歌曲匹配，只展示与当前播放歌曲关联的动态（决议 D6）

**公开域与私密域**（决议 D2）：公开域可被推荐、搜索、分类展示，自由进入；私密域凭邀请链接或密码进入。域无人数上限，全员退出后自动消失。

## 角色设计

| 角色 | 权利 | 动机 |
|------|------|------|
| 域主 Host | 输入域名、选择一个**必选场景**并选择**恰好 3 首**初始歌曲即可创建；可选上传一次域封面，不上传则锁定第一首歌封面；可在高级设置中配置公开/私密和标签过滤，创建后可编辑域名与场景但不能更换封面；**无踢人权限** | 表达审美、聚集同好 |
| 同频者 | 收听、上传歌曲（5 分钟冷却）、上传歌曲时可选附图、点赞/收藏/emoji 互动、关注上传者、与关注关系中的用户私信、撤回自己的图片 | 陪伴感、发现好歌、低门槛参与 |

## 曲风标签体系：域的风格治理

> 决议来源：2026-09-23 会议 D1 + 2026-09-24 会议 D5（双模式升级）

**问题**：域的风格若靠域主口头约束无法执行，若由系统统一规定又失去个性。

**方案**：

1. **标签五分类**：系统为曲库歌曲统一打标，标签分**语言、年代、风格、场景、情绪**五类（如：语言=日语，风格=City Pop，场景=夜跑，情绪=舒缓）
2. **过滤为可选高级设置**：快速创建默认“不限制”；域主需要治理曲风时再选择——
   - 「禁止含这些标签的音乐」（黑名单）
   - 「仅允许含这些标签的音乐」（白名单，2026-09-24 新增，回答了 v1 未决问题）
   - 交互顺序：先选择过滤模式，再在语言、年代、风格、情绪四类标签中选择；域的必选场景独立用于发现分发，不重复放入音乐过滤。启用黑名单或白名单时至少选一个。
   - 黑名单命中任一已选标签即拒绝；白名单在同一类别内取 OR、不同类别间取 AND（例如“日语/韩语 + 流行 + 舒缓”）。
3. 命中过滤规则的歌曲无法在该域被上传；番茄钟时段白名单（docs/02 D3）与域级过滤**叠加生效**

风格治理 = 域主按需设置过滤规则 + 系统保证标签准确性。**域主没有踢人权限**；启用过滤的域由标签规则维持曲风秩序。

## 审美反馈：让"被认可"看得见

> 决议来源：2026-09-23 会议 D2 + 2026-09-24 会议 D7（收敛为克制版）

- **微光提示**：你上传的歌在播放时被收藏，页面边缘出现短暂柔光提示——不用强震动或夸张动画（2026-09-24 定稿，取代 v1"实时特效"）
- **互动三件套**：歌曲点赞、收藏、emoji 轻互动（爱心/大笑/点赞）；可**关注**上传者（轻入口，不改变播放体验）
- **私信**：Following 列表和已关注用户主页提供 Message 入口；双方任意一方仍保持关注即可双向回复，消息仅双方可读，首版只支持文字
- **边界**：不支持评论区、群聊、图片／语音私信和离线推送
- **去游戏化**（2026-09-24 决议 D7）：不做积分、等级、勋章系统 → v1 的「歌品值」体系**取消**，"我的"页改为 我的域 / 我的上传 / 关注 / 收藏（功能型主页）

审美认可仍然存在，但从"量化攀比"改为"当下的、轻量的被看见"。

## 远景方向：品牌联名域

与线下品牌（咖啡店、连锁健身房等）联名：品牌总部或单门店创建自己的域，用户**定位到店**才能进入，门店音响播放的音乐由域内点歌决定——顾客真正参与门店氛围共建。把"域"从线上场景延伸到线下商业空间，是 B 端合作与生态化的抓手（详见 03、04 文档）。

## 视觉规范（2026-09-24 定稿，决议 D8）

- **基调**：日式简约 + 苹果风克制留白；黑白灰低饱和冷调为主
- **主题色**：不同主题域使用低饱和莫兰迪色点缀——学习域浅灰蓝 / 健身域低饱和青绿 / 旅行域浅沙色或天蓝 / 日系域淡米灰或浅樱粉
- **玻璃拟态**：毛玻璃卡片/导航栏/弹窗，轻微边缘高光 + 软阴影 + 半透明背景；玻璃卡片与普通卡片要有区分
- **图形语言**：大圆角统一、极简细线图标、软阴影、大量留白
- **禁忌**：复杂渐变、霓虹、科技感、赛博朋克、拟物风、卡通插画、夸张动效、强提醒式游戏化视觉

（v1 此处为"待调研"，2026-09-24 会议已定稿，前端按此换肤。）

## 与竞品的差异

| 产品 | 模式 | 我们的差异 |
|------|------|-----------|
| QQ音乐/网易云歌单 | 静态、异步 | 域是实时流动的"过程"，且按场景而非曲风组织 |
| 一起听 | 1v1 / 小圈子，需先有好友 | 域是开放的陌生人同频，场景即入口 |
| 语音直播/电台 | 主播单向输出 | 域内人人可点歌，审美由社区共建 |
| 豆瓣小组/贴吧 | 异步图文 | 域以实时音频流为粘合剂，图文是副产品 |

## 命名建议

产品名「同频」，核心单位叫「域」（Zone）。Slogan 候选：

- "此刻，和你做同一件事的人，在听同一首歌"
- "正在做的事，就是最好的歌单分类"
